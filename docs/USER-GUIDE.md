# Dota Archive 中文使用教程

这篇教程以 1.0.8 为例，介绍如何查询历史版本、下载客户端，以及检查客户端是否能用于本地测试。

## 一、下载并打开软件

打开 [GitHub Releases](https://github.com/hansong1994/DotaArchive/releases/latest)，在 **Assets** 中下载 `DotaArchive-1.0.8-win-x64.zip`。不要把页面上的 `Source code (zip)` 当成软件安装包。

将压缩包完整解压到英文路径，例如：

```text
D:\DotaArchive
```

双击其中的 `DotaArchive.exe`。不要直接在压缩包内运行，不要只复制 EXE，也不要删除 `data`、`engine` 等随包文件夹。

运行环境：Windows 10/11 64 位、[.NET Framework 4.8](https://dotnet.microsoft.com/download/dotnet-framework/net48)、[Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。只有缺少对应运行库时才需要从微软官网安装。普通使用不需要 .NET SDK、Codex 或命令行。

## 二、先设置保存位置

在“下载设置”中点击“更改”，选择游戏客户端保存位置，例如：

```text
D:\DotaArchiveClients
```

整个路径都应使用英文、数字和常规 ASCII 符号，不能包含中文目录名。不同 Build 会保存在不同子目录中，先检查磁盘剩余空间。

“Steam 账户名 · 可选”可以留空，之后通过手机 Steam App 扫码授权。“Steam 直连”可以先保留默认设置。

## 三、按时间查询

1. 在“查找历史版本”中选择“按北京时间”。
2. 输入时间，例如 `2019-06-06 12:00:00`。输入固定按北京时间 UTC+8 解释，不随 Windows 的时区设置改变。
3. 选择“此前最近版本”或“此后最近版本”。
4. 点击“仅查找”，先核对结果，再决定下载。

两个方向都严格排除恰好相等的时刻：

| 选择 | 含义 |
| --- | --- |
| 此前最近版本 | 找到输入时间之前，离它最近的一次公开更新 |
| 此后最近版本 | 找到输入时间之后，离它最近的一次公开更新 |

软件优先使用本地归档。已经覆盖的历史不需要再去 SteamDB 查询；本地覆盖不足时，时间查询可能打开内置 SteamDB 浏览器，需要用户完成登录或验证。

## 四、按补丁号查询

1. 把查询方式改为“按补丁号”。
2. 输入完整补丁号，例如 `7.00`、`7.01` 或 `7.22b`。
3. 选择“此前最近版本”或“此后最近版本”。
4. 点击“仅查找”。

软件先从内置日期表查到该补丁的公告时间，再按时间查询同样的规则匹配本地历史。如果来源只有发布日期，则采用日期表记录的该日起点，结果中会显示时间精度和时区约定。

**这里的补丁号用于确定查询基准，不是对结果所属补丁或首发构建的认证。** 选择“此前”可能得到上一个补丁，选择“此后”也可能得到后续更新。请核对结果中的实际时间与 Build，而不要仅凭目录名前面的补丁号判断版本。

补丁号查询全程在本地完成。日期表未收录、资料存在冲突，或历史覆盖不足时，会明确提示；可以改用时间查询。当前目录不是全部补丁号的完整列表。

## 五、核对结果并下载

“版本详情”会显示匹配规则、查询基准、Build 编号、实际匹配时间、时间来源和 Depot/Manifest 组合。

Build 是一次构建的编号；Depot 可以理解为客户端的一部分文件；Manifest 指定这部分文件的具体历史状态。软件会还原整套组合，下载时不需要手动填写编号。

确认结果后点击“下载 / 继续”。如果希望查到结果后立即下载，也可以直接使用“查找并下载”。

需要 Steam 授权时：

1. 在“Steam 授权”页查看二维码。
2. 打开手机 Steam App，扫描二维码并确认本次登录。
3. 二维码过期时，点击“刷新登录二维码”，等待新码出现后重新扫描。

刷新二维码会结束旧授权请求，再生成新的请求，已有下载文件会保留。SteamDB 网站登录和游戏下载所用的 Steam 授权是独立流程，完成一个不代表另一个已经完成。

软件会先获取各 Depot 的原始 Manifest，再整理文件计划、下载并校验。准备清单期间可能还没有文件下载百分比，请结合任务状态查看进度。

## 六、停止和恢复下载

需要中断时点击“停止任务”。已保存的文件会保留，但未完成任务不会被标记为下载成功。

- 同一次运行中，可以点击“下载 / 继续”恢复当前版本。
- 下次打开软件后，点击右上角“恢复已有下载”，选择**具体版本文件夹**，不是存放全部版本的父目录。

例如，应该选择类似 `7.01-2016-12-21-build1532815` 的目录，而不是 `DotaArchiveClients`。目录名称以实际查询结果为准。

恢复使用目录中保存的准确 Build/Manifest 计划。原始本地清单齐全时，会先离线校验文件；清单或文件不完整时，仍可能需要 Steam 授权继续下载。

不要删除版本目录中的 `.dota-archive-browser`、`.DepotDownloader`、`manifest_*.txt`，这些文件用于恢复和校验。可以通过“打开版本目录”找到当前客户端。

## 七、校验并进行本地测试

下载后软件会校验文件，也可以手动点击“完整文件校验”。校验通过后再点击“启动本地测试”。

测试前先退出其他正在运行的 Dota 2，并打开 Steam 客户端、登录自己的账号。启动后请逐项检查：

1. 能否进入游戏主菜单。
2. 能否创建或进入本地机器人对局并加载地图。
3. 英雄是否能移动、释放技能，所需资源是否正常显示。

“进程已启动”和“文件校验通过”都不等于对局测试成功。老客户端可能受当前 Windows、驱动或 Steam 环境影响；本工具不承诺旧客户端能够进行当前正式服务器的联机匹配。

如果出现 `icu_52`、`icuuc.dll`、`icui18n.dll`、`v8.dll` 相关入口点错误，请使用新版软件的“恢复已有下载”打开该版本，再通过“启动本地测试”启动。软件会对检测到的旧 ICU 52 冲突进行兼容处理，并保留原件：

```text
_compatibility\icu52\originals
```

请保留这些备份，完整文件校验也需要核对它们。不要从不明网站下载 DLL 随意替换。

## 八、更新版本资料

1. 点击“更新版本资料”。
2. 在内置“SteamDB 浏览器”中，按网页要求完成登录或验证。
3. 点击“已完成验证，继续”。
4. 等待新增历史衔接和完整性检查通过，再查看界面顶部的资料截止时间。

这一步更新的是历史构建记录，不会自动下载游戏。只有新数据核对成功，软件才会发布新的本地数据库。

**“更新版本资料”不等于更新补丁发布日期表。** 补丁日期表随软件新版分发。新补丁号暂未收录时，可以先更新历史资料，再按时间查询。

发生 HTTP 403、429 或需要人工验证时，应停止该次查询并遵守提示中的等待要求，不要连续重复点击。软件不会绕过网站验证和访问限制，也没有默认开启定时抓取。

## 九、常见问题

### 查询成功，为什么下载失败？

查询成功说明本地资料能够还原所选历史组合，不代表 Steam 仍会授权下载全部历史文件。网络、Steam 登录、Depot 密钥、Manifest 或文件获取都可能失败。

“此版本因未定义的错误无法下载”是统一提示。请查看“任务记录”，底层诊断通常保存在版本目录的 `.dota-archive-browser/diagnostics` 中。反馈前先检查并删去账号、授权信息等个人资料。

### 能否保证所有旧版本都能用？

不能。历史记录完整、文件可下载、文件校验通过、客户端正常运行是不同的检查阶段。部分早期版本可能无法下载，部分版本仍需要实际运行测试。

既有测试中，7.01 / Build 1532815 经兼容处理后进入过菜单并载入本地机器人地图，但移动、施法仍未完成核实；不能据此宣称所有客户端都已通过实战测试。

### 切换方向后为什么需要重新查找？

改变时间、补丁号或前后方向后，之前的查询结果已经不再对应当前条件。软件会清除旧选择，防止下载或启动错误版本。

### 升级软件会不会丢失客户端？

将新发布包完整解压到新的英文目录，再打开新版本。客户端仍保存在自己选择的游戏目录中；在新版本中用“恢复已有下载”打开即可。

SteamDB 浏览器登录资料和后续同步数据库保存在 `%LOCALAPPDATA%\DotaArchive\BrowserPrototype`；Steam 下载授权缓存由下载引擎另行保存在当前 Windows 用户的隔离存储中。它们不在公开发行包中。不要把这些私人缓存上传到 GitHub 或发送给其他人。
